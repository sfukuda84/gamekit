# gamekit-direction スキル（G3: 方向性の 3 案 → 選択）

同じ種から、プレイ体験の違う 3 つの方向を作って比べる（speckit-architecture の「3 系統の比較」と同じ形）。ここで選んだ方向が、壁打ち（G4）の出発点になる。

パスは `.gamekit/config.yaml` の `paths` で読み替える。進捗の記録とモードは [`gamekit-bootstrap`](../gamekit-bootstrap/SKILL.md) の §3・§7 に従う。

## 1. 入力

- `docs/concept/seed.md`（原文、コアファンタジー、ピッチ、選択）
- `docs/research/competitors.md`（参考作品、ジャンルの定石、空いている席、差別化の仮説、IP の注意点、種への影響）
- 引数の希望

どちらかがなければ、欠けている工程（`gamekit-seed` / `gamekit-research`）を案内する。`competitors.md` の「種への影響」を最初に読む。

## 2. 手順

### ステップ 1: 発想を広げる

選んだピッチを中心に置き、マンダラート（3×3 の中心にピッチ、周囲 8 マス）で要素を広げる。周囲 8 マスは次の観点で埋める。

1. 繰り返す行為（動詞）
2. 意思決定（何と何を天秤にかけるか）
3. 成長と解放
4. 資源と経済
5. 失敗と再挑戦
6. 舞台とトーン
7. プレイヤーの期待（ジャンルの定石）
8. 空いている席

有望なマスには SCAMPER の 7 つの操作を当て、案の候補を作る。

| 操作 | 例 |
|---|---|
| 代える | 繰り返す行為、舞台、プレイヤーの立場を代える |
| 組み合わせる | 別ジャンルのループを組み合わせる（例: 農業 × 借金返済の経営） |
| 応用する | 他の分野の仕組みを借りる（例: 物流の仕組みを戦闘に） |
| 修正・拡大・縮小する | 規模や時間を極端に変える（1 日 3 分、100 年） |
| 転用する | 資源や道具を別の目的に使う |
| 除く | 定番の要素を抜く（戦闘のない RPG、お金のない経営） |
| 逆にする | 立場や順序を入れ替える（守る側、壊す側） |

この作業は `direction.md` の「発想メモ」に残す。完成させる必要はない。

### ステップ 2: 3 案を作る

候補から、**プレイ体験が互いに重ならない 3 案**を選ぶ。

- 3 案は、コアループ（繰り返す行為と意思決定）、規模、トーンのうち、少なくとも 2 つが違うようにする。
- 1 案は、種の原文に最も忠実な案にする。
- 1 案は、`competitors.md` の「まだ空いている席」を最も強く狙う案にする。
- 1 案は、規模を最も小さくし、少人数・短期間で垂直スライスまで作れる案にする（ほかの 2 案のどちらかと兼ねてもよい。そのときは残りの 1 案を自由にする）。

案ごとに、次を書く。

| 項目 | 内容 |
|---|---|
| 一言 | この案を 1 文で |
| ピッチ | 「〇〇で△△する□□」 |
| コアファンタジー | プレイヤーが何者になって、何をする快感か |
| コアループ | 秒・分・時間の 3 層で、繰り返す行為 |
| 主要な意思決定 | プレイヤーが何と何を天秤にかけるか（2〜3 個） |
| progression の型 | 成長と解放の仕組み（レベル、装備、恒久強化、図鑑、施設など） |
| 経済の骨格 | 主な資源と、入口と出口 |
| 失敗と再挑戦 | 何で失敗し、何が残って何を失うか |
| ジャンルの定石 | 満たす必須要素と、意図的に外すもの |
| 参考作品との差 | `competitors.md` の重なりが大きい作品に対して、何で差をつけるか |
| トーン | 見た目と雰囲気の方向 |
| 規模 | 遊べる時間、要素の数、人月の目安（何人で何か月）、垂直スライスの範囲 |
| リスク | この案の弱点と、失敗したときの症状（中盤で飽きる、作業になる、など） |
| 検証の難しさ | コアループの面白さを、机上やグレーボックスでどれだけ早く確かめられるか |

### ステップ 3: 比較して提示する

3 案を比較表にまとめ、推奨案と理由を添えて示す。比較の観点は次の 8 つ。

1. 種への忠実さ
2. 空いている席を狙えているか
3. 参考作品との差の明確さ
4. ジャンルの定石の満たしやすさ
5. 長く遊ばれる耐性（中盤・終盤で失速しないか）
6. 規模と、作り手の体制での実現しやすさ
7. 検証の早さ
8. リスクと IP の危うさ（オマージュ元に近すぎないか）

安易な「外し」は警告する。定番の仕組みを逆にしただけで、プレイ体験が変わらない案は、差別化として数えない。

### ステップ 4: 選択

- **対話モード**: AskUserQuestion で案を選んでもらう。推奨案を先頭に `(Recommended)` 付きで置く。「組み合わせる」（例: A のループに C の規模）も受け付け、組み合わせた案を 1 つにまとめ直して、もう一度確かめる。
- **自動モード**: 推奨案を採用し、`docs/auto-decisions.md` に記録する。ジャンル、プラットフォーム、規模は、見直しの優先度を「高」にする。

選んだ案を `direction.md` の「選択」に書く。選ばなかった案は消さず、`docs/concept/backlog.md` にも要点を残す（後で要素を拾えるように。様式は `gamekit-sparring` の [templates/backlog.md](../gamekit-sparring/templates/backlog.md)）。

## 3. 出力

- `docs/concept/direction.md`（様式: [templates/direction.md](./templates/direction.md)）
- `docs/concept/backlog.md`（選ばなかった案の要点を追記）

終わったら `gamekit-bootstrap` §3 の形で `G3` を記録する（単独で実行したときも記録する）。

## 4. 完了報告

- 3 案の一言と、選んだ案（組み合わせた場合はその内容）
- 選んだ案のコアファンタジー、コアループ、主要な意思決定、規模
- 次の案内: `gamekit-sparring`（G4）
