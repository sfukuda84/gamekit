# gamekit-seed スキル（G1: 種 → コアファンタジーとピッチ）

ユーザーの 1 文を、以降の調査と方向性の検討に使える形にする。まだ何も決めない。**入力の 1 文は一字も変えずに残す。**

パスは `.gamekit/config.yaml` の `paths` で読み替える。進捗の記録とモードは [`gamekit-bootstrap`](../gamekit-bootstrap/SKILL.md) の §3・§7 に従う。

## 1. 引数

```text
$ARGUMENTS
```

- `--auto` を取り除いた残りを、種の 1 文として扱う。
- 引数がなければ、`docs/concept/core-concept.md` を種として読む。それもなく、`seed.md` もなければ、次のように聞く（自動モードでは止まる）。

  > 作りたいゲームを 1 文で教えてください。「〇〇になって△△するゲーム」でも、遊びの断片でも、オマージュしたい作品名だけでも構いません。対象のプラットフォームが決まっていれば、それも添えてください。

- `seed.md` がすでにあれば、原文を残したまま「追記（YYYY-MM-DD）」の節を足す（更新モード）。
- 既存のプロジェクトに取り込んだとき（企画書や `docs/concept/` の資料がある）は、それを読み、書いてあることを「要素」に写して出典を書く。質問し直さない。

## 2. 手順

1. **原文を記録する。** 種の 1 文を、そのまま `seed.md` の「原文」に書く。
2. **要素を分ける。** 原文から読み取れることを、次の表に分ける。原文にないものは「未定」と書き、推測で埋めない。

   | 要素 | 内容 |
   |---|---|
   | プレイヤーが演じるもの | 何者になるか（職業、立場、生き物、集団の長など） |
   | 繰り返す行為（動詞） | 何を繰り返すか（育てる、撃つ、並べる、交渉する…） |
   | 目的・勝ち負け | 何を目指し、何で失敗するか |
   | 舞台とトーン | 世界、時代、雰囲気（明るい、ハード、牧歌的…） |
   | ジャンルの手がかり | |
   | プラットフォーム・操作の手がかり | |
   | 参考作品・オマージュ元の手がかり | |

3. **コアファンタジーを書く。** 「プレイヤーが〇〇になって、△△する快感」の形で 1〜2 文。世界観や物語ではなく、**繰り返す行為と、その結果の手応え**で書く。
4. **「もしも〜なら」に言い換える。** 原文を、状況を問う形に 3 通り言い換える。1 つは原文に忠実に、残り 2 つは立場・規模・制約のどれかをずらす（例: 「もしも農場が借金のかたに取られかけていたら」「もしも 1 日が 3 分しかなかったら」）。
5. **1 文のピッチの案を 3 つ作る。** 各案は「〇〇で△△する□□（ジャンル）」の形を基本にし、仮題を付ける。3 案は、繰り返す行為・規模・トーンのうち少なくとも 1 つを変える。
6. **4 条件で採点する。** 各案を次の 4 条件で ◎／○／△ に評価し、弱い条件をどう強くするかを 1 行で添える。

   | 条件 | 見るもの |
   |---|---|
   | 動詞で遊びが浮かぶ | 読んだだけで、プレイヤーが手で何をするかが思い浮かぶか |
   | 新しさ | ジャンルの定番に、意外な組み合わせや制約が 1 つ足されているか |
   | 誰がどこで遊ぶか | プレイヤー像と、遊ぶ場面（通勤の 5 分、週末の数時間など）が分かるか |
   | 規模が見える | 作る範囲（遊べる時間、要素の数）の見当が付くか。少人数で作れる大きさか |

7. **プレイヤー像と遊ぶ場面、プラットフォームの想定を書く。** 原文と手がかりから分かる範囲で書き、残りは「未定（G4 で決める）」とする。
8. **参考作品とオマージュ元の候補を挙げる。** 原文に名前が出ている作品は、必ずここに書く。AI が思い付いた作品は「候補（未確認）」として書き、G2 で実在と中身を確かめる。オマージュ元がある場合は、何を受け継ぎたいか（仕組み・雰囲気・テーマ）を分けて書く。
9. **調査の論点を挙げる。** G2（参考作品の調査）で調べるべきことを 5〜10 個挙げる。参考作品の系統、ジャンルの定石、プレイヤーの不満、オマージュ元の固有の要素（持ち込んではいけないもの）、プラットフォームの事情など。
10. `seed.md` を書き、ユーザーに示す。

### 対話モード

- 3 案のうち、どれを調査の軸にするかを質問する。1 つに絞らず「全部を材料に調べる」も選べる。推奨案を先頭に `(Recommended)` 付きで置く。
- 回答を `seed.md` の「選択」に書く。

### 自動モード

- 採点が最も高い案を調査の軸にし、`docs/auto-decisions.md` に記録する（見直しの優先度: 中）。`seed.md` の「選択」には、`(auto)` と理由を書く（例: 「調査の軸: A（auto）。理由: 採点が最も高く、原文に忠実」）。

## 3. 出力

`docs/concept/seed.md`（様式: [templates/seed.md](./templates/seed.md)）

仮題を決めたら、`.gamekit/config.yaml` の `title` が空なら書く。終わったら `gamekit-bootstrap` §3 の形で `G1` を記録する（単独で実行したときも記録する）。

## 4. 完了報告

- 原文、コアファンタジー、選んだピッチと仮題
- 参考作品・オマージュ元の候補
- 調査の論点
- 次の案内: `gamekit-research`（G2）
